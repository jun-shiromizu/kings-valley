# Kings Valley プロダクト要件

## 1. 文書情報

- 文書名: Kings Valley プロダクト要件
- 位置づけ: 本アプリのプロダクト要件に関する正本
- 対象: 初期リリース
- ステータス: 承認済み

本書とほかの文書で記述が異なる場合は、本書を優先する。要件を変更する場合は、実装に先立って本書を更新する。

## 2. プロダクト概要

Kings Valley は、5 x 5 マスの盤上でプレイヤーと COM が対戦する、1人用のターン制アブストラクトゲームである。各駒は途中で止まれず、盤の端またはほかの駒にぶつかる直前まで一直線に移動する。プレイヤーは自分の王様を中央マスに停止させることを目指す。

## 3. 目的

- ルールを知らない利用者でも、画面上の誘導だけで対局を完了できること
- マウスとタッチのどちらでも、同じ操作で快適に遊べること
- スマートフォン、タブレット、PC で盤面全体を視認し、誤操作なく駒を動かせること
- 認証やサーバーを必要とせず、GitHub Pages 上で対局できること

## 4. 対象範囲

### 4.1 初期リリースに含むもの

- プレイヤー対 COM の1人用対局
- 先手、後手、ランダムの選択
- easy、normal、hard の難易度選択
- 合法手の判定と移動可能方向の表示
- 勝利、敗北、引き分けの判定
- 全難易度でランダムに合法手を選ぶ COM
- 対局終了後の設定を引き継ぐ再戦とトップページへの遷移
- レスポンシブ対応
- GitHub Pages への自動デプロイ

### 4.2 初期リリースに含まないもの

- プレイヤー同士のローカル対戦またはオンライン対戦
- 思考型 COM と難易度ごとに異なる COM 戦略
- 認証、ユーザー登録、戦績保存
- 対局の中断保存、棋譜、リプレイ
- 効果音、BGM、多言語対応

## 5. 用語

| 用語 | 定義 |
| --- | --- |
| プレイヤー | 端末を操作する人間側の陣営 |
| COM | アプリが操作する対戦相手側の陣営 |
| 王様 | 各陣営が1個ずつ持つ、勝利条件の対象となるメイン駒 |
| 兵士 | 各陣営が4個ずつ持つ補助駒 |
| 中央マス | 5 x 5 盤面の中央にある1マス |
| 合法手 | ルールに従い、現在位置とは異なるマスへ移動できる手 |
| 局面 | 全駒の種類、所有者、位置、および次の手番を組み合わせた状態 |
| 難易度 | COM の難易度設定。easy、normal、hard のいずれか |

## 6. ゲームルール

### 6.1 盤面と駒

- 盤面は縦5マス、横5マスとする。
- 各陣営は王様1個と兵士4個、合計5個を持つ。
- プレイヤーから見て、プレイヤー側を盤面の手前、COM 側を奥として常に表示する。
- 初期配置では、COM の5駒を最奥の1列、プレイヤーの5駒を最手前の1列に置く。
- 各陣営とも王様をその列の中央に置き、左右に兵士を2個ずつ置く。
- 中央マスには王様と兵士のどちらも進入、通過、停止できる。

### 6.2 手番

- 先手から開始し、1回の移動が完了するたびに相手へ手番を交代する。
- トップページで「先手」を選ぶとプレイヤーが先手、「後手」を選ぶと COM が先手になる。
- 「ランダム」を選ぶと、対局開始時にプレイヤーと COM のどちらが先手かを等確率で決定する。
- COM の手番中、プレイヤーは駒を操作できない。

### 6.3 駒の移動

- 駒は現在位置から縦、横、斜めの8方向のいずれかへ直進する。
- 駒は、進行方向にある盤の端、またはほかの駒にぶつかる直前のマスで停止する。
- 移動中に方向を変えることはできない。
- 移動途中の任意のマスに停止することはできない。
- ほかの駒を飛び越したり、同じマスに重なったりすることはできない。
- 隣接するマスが盤外またはほかの駒である方向は、移動距離が0となるため選択できない。
- 移動後の停止位置が現在位置と異なる方向だけを合法な移動方向とする。

### 6.4 対局終了

移動完了後、次の順序で対局終了を判定する。

1. 移動した王様が中央マスに停止した場合、その王様を所有する陣営の勝利とする。
2. 勝利が決まらず、同一局面が対局中に3回現れた場合、引き分けとする。
3. 勝利も引き分けも決まらない場合、手番を相手へ交代する。
4. 新しい手番の陣営に合法手が1つもない場合、その陣営の敗北とする。

兵士が中央マスに停止しても勝利にはならない。兵士が中央マスを占有している間、ほかの駒はそのマスへ進入できない。

## 7. 機能要件

### FR-01 トップページ

- アプリ名を表示する。
- プレイヤーの手番順として「先手」「後手」「ランダム」の3択を表示する。初期選択は「ランダム」とする。
- 「先手を選ぶ」ラベルは、従来の見出し表示より小さいフォントサイズで表示する。
- 手番順の下に「ゲーム難易度を選ぶ」ラベルと、easy、normal、hard の単一選択肢を表示する。初期選択は easy とする。
- 手番順と難易度の選択肢は一度に1つだけ選択でき、アクセシブルな名前を持ちキーボードで選択できる。
- 「ゲームスタート」を選択すると、指定した手番順と難易度で新しい対局を開始し、ゲームページへ遷移する。

### FR-02 ゲームページの表示

- 5 x 5 の盤面、全10駒、中央マスを表示する。
- プレイヤーと COM、および王様と兵士を視覚的に判別できるようにする。
- 現在の手番がプレイヤーか COM かを常に表示する。
- 対局開始時に決定した先手を表示し、利用者が結果を確認できるようにする。
- 盤面の向きは手番順にかかわらず、常にプレイヤーを手前、COM を奥とする。

### FR-03 駒の選択

- プレイヤーの手番中にプレイヤーの駒をクリックまたはタップすると、その駒を選択状態にする。
- 選択中の駒を再度選択すると、選択を解除する。
- 選択中に別のプレイヤー駒を選ぶと、選択対象を切り替える。
- COM の駒および合法手を持たない駒は選択できない。
- 選択中の駒は、非選択の駒と明確に区別して表示する。

### FR-04 移動方向の選択

- 駒を選択すると、その駒が移動できる全方向を矢印で表示する。
- 矢印は移動方向と操作対象を明確に示し、盤面や駒の識別を妨げない位置に表示する。
- 矢印をクリックまたはタップすると、その方向で確定する停止位置まで駒を移動する。
- 移動できない方向には矢印を表示しない。
- 1回の入力で複数回移動しないよう、移動処理中の追加入力を無効にする。

### FR-05 COM

- COM は自分の手番になると自動的に着手する。
- easy、normal、hard の全難易度で、COM は合法手だけから完全にランダムに1手を選ぶ。現時点では難易度による挙動差はない。
- COM の選択から移動完了まで、利用者が着手を認識できる短い待ち時間を設ける。難易度によってゲームルール、着手待機、またはランダム戦略を変更しない。
- COM に合法手がない場合、ルールに従って COM の敗北とする。
- COM の着手待機タイマーは、対局の終了、明示的なセッション破棄、またはゲーム画面を所有するコンポーネントの破棄時に取り消す。破棄済みのセッションで予約済みの着手を実行してはならない。

### FR-06 終局表示

- 終局時、盤面への操作を無効にする。
- プレイヤー勝利時は勝利、COM 勝利時は敗北、反復局面成立時は引き分けを大きく表示する。
- 「もう一度」を選ぶと、直前と同じ手番順と難易度の設定で盤面を初期化し、新しい対局を開始する。
- 直前の手番順設定が「ランダム」の場合、「もう一度」のたびに先手を再抽選する。難易度は再抽選しない。
- 「トップページ」を選ぶとトップページへ戻る。

### FR-07 状態管理と再読み込み

- 対局状態はブラウザ内のメモリだけで管理し、外部へ送信しない。
- ゲームページを再読み込みした場合、進行中の対局は復元せず、トップページへ戻す。
- 同一局面の出現回数は対局ごとに初期化する。

## 8. 画面と遷移

| 画面 | ルート | 主な操作 |
| --- | --- | --- |
| トップページ | `#/` | 手番順と難易度の選択、対局開始 |
| ゲームページ | `#/game` | 駒の選択、移動、再戦、トップへの移動 |

- GitHub Pages で直接アクセスした際の 404 を避けるため、Vue Router のハッシュ履歴を使用する。
- 未定義のルートへアクセスした場合はトップページへ遷移する。

## 9. UI・アクセシビリティ要件

- 画面幅320px以上のスマートフォン、タブレット、PC の主要ブラウザで利用できること。
- 盤面は正方形を維持し、横スクロールなしで表示すること。
- タッチ操作の対象は十分な大きさと間隔を確保すること。
- 色だけに依存せず、形状、記号、ラベルなどを併用して陣営、駒種、選択状態、手番を識別できること。
- キーボードでも手番順、難易度、駒、移動方向、終局後の操作を選択できること。
- 操作可能な要素には視認できるフォーカス表示と、内容を表すアクセシブルな名前を設定すること。
- COM 思考中および終局結果を支援技術へ通知できること。
- `prefers-reduced-motion` が有効な場合は、移動や画面表示のアニメーションを抑制すること。
- 文字、駒、矢印、終局表示が互いに重ならず、すべての対象画面幅で内容を判読できること。

## 10. 非機能要件

### 10.1 技術構成

- Vue 3、TypeScript、Vite を使用する。
- Vue Composition API を使用する。
- Vue Router を使用する。
- ゲームルールは UI から分離し、同じ入力に対して同じ結果を返すロジックとして実装する。
- 外部 API、バックエンド、認証機能は使用しない。

### 10.2 品質

- TypeScript の厳格な型チェックを有効にする。
- ESLint およびプロジェクトで採用するフォーマッターの検査を通過すること。
- 合法手、停止位置、手番交代、勝敗、合法手なし、同一局面3回、COM の選択対象を Vitest で単体テストする。
- 難易度の初期値、開始時の保持、再戦時の引継ぎ、および全難易度でのランダムかつ合法な COM 着手を Vitest で単体テストする。
- 対局開始、プレイヤーの着手、COM の着手、終局後の再戦とトップ遷移を Playwright で E2E テストする。
- E2E テストで easy の初期選択、難易度選択後の開始、再戦時の設定引継ぎを確認する。
- 乱数へ依存する処理は、テスト時に結果を制御できる設計とする。

### 10.3 配信

- 静的ファイルとしてビルドできること。
- GitHub Actions の最小構成のワークフローにより GitHub Pages へデプロイすること。
- `main` ブランチへの反映を契機に、ビルドとデプロイを実行すること。
- リポジトリ名を含む GitHub Pages のサブパスでもアセットを読み込めるよう、Vite の `base` を設定すること。
- クライアントへ秘密情報を含めないこと。

## 11. 受け入れ基準

1. 利用者が先手、後手、ランダムと、easy、normal、hard のいずれかを指定して対局を開始でき、難易度の初期選択は easy である。
2. 手番順と難易度の各選択肢は、アクセシブルな名前を持ちキーボードで選択できる。先手選択ラベルは従来の見出しより小さく表示される。
3. 初期盤面で両陣営の王様が各端列の中央、兵士がその左右に配置される。
4. プレイヤーの駒を選ぶと合法な方向だけに矢印が表示され、選んだ方向の最終到達マスまで移動する。
5. 駒は途中停止、方向転換、ほかの駒の飛び越し、同一マスへの重なりを行えない。
6. 王様または兵士が中央マスを通過または停止でき、王様が中央マスに停止した場合だけ所有陣営が勝利する。
7. easy、normal、hard の全難易度で COM が毎手、現在の局面に存在する合法手だけからランダムに着手し、COM 先手の開始時にも難易度によらず短い待機後に1回だけ着手する。
8. COM の予約済み着手は、対局終了、セッション破棄、またはゲーム画面の破棄後に実行されない。
9. 手番側に合法手がない場合、その陣営の敗北として対局が終了する。
10. 同一の駒配置と手番が3回現れた場合、引き分けとして対局が終了する。
11. 終局後に盤面を操作できず、手番順と難易度を引き継ぐ再戦またはトップページへの移動を選べる。ランダム手番順は再戦ごとに先手を再抽選し、難易度は引き継ぐ。
12. 320px幅の画面、タッチ操作、マウス操作、キーボード操作で主要導線を完了できる。
13. 単体テストで難易度の初期値・開始時の保持・再戦時の引継ぎ・全難易度でのランダムかつ合法な COM 着手を確認し、E2E テストで easy 初期選択・難易度選択後の開始・再戦時の設定引継ぎを確認する。
14. 単体テスト、E2E テスト、型チェック、Lint、フォーマット検査、プロダクションビルドが成功する。
15. `main` ブランチの内容を GitHub Actions から GitHub Pages へデプロイできる。

## 12. 要件変更時の扱い

新しいルールや機能を追加する場合は、対象範囲、機能要件、受け入れ基準を更新する。ルール変更では、少なくとも合法手判定、終局判定、単体テストへの影響を確認する。
