## 2. 実装方針

### 2.1 基本方針

- Vue 3、TypeScript、Vite、Composition API、Vue Router を使用する。
- ゲームルールは `src/domain/` に純粋 TypeScript として実装し、Vue、DOM、タイマーから分離する。
- 盤面計算、合法手、終局、COM の選択は、UI 実装より先に Vitest で固定する。
- 対局状態はメモリだけに保持し、認証、外部 API、localStorage、バックエンドを追加しない。
- 乱数は関数として注入できるようにし、単体テストと E2E で結果を制御可能にする。
- 各フェーズは、対象テスト、型チェック、Lint の成功を完了条件に含める。
- GitHub Pages 固有の base path とハッシュルーティングを初期構築時から組み込む。

### 2.2 UI の方向性

- 盤面を主役とし、トップページをマーケティングページにしない。
- 紙のゲーム盤を思わせる明るい背景、濃いインク色、プレイヤー側の赤、COM 側の青緑、中央マスの金を基調にする。
- 王様は王冠、兵士は盾など、色以外の形状でも区別できるアイコンを使用する。
- 方向操作には Lucide の矢印アイコンを使用し、各ボタンへ accessible name を付ける。
- 背景や盤面には控えめなパターンまたは質感を使い、盤面と操作情報の視認性を優先する。
- 盤面は常に正方形を維持し、320px 幅からデスクトップまで横スクロールを発生させない。

## 5. 品質ゲート

実装完了時は次のコマンドがすべて成功することを必須とする。

```sh
npm run type-check
npm run lint
npm run format:check
npm run test:unit
npm run test:e2e
npm run build
```

追加の判断基準:

- domain ロジックに Vue、DOM、タイマーへの依存がない。
- 乱数を固定したテストが順序や実行環境に依存しない。
- skipped、focused、無効化されたテストが残っていない。
- ブラウザコンソールに未処理例外や警告がない。
- 生成物、テストレポート、秘密情報がコミットに含まれていない。
- 要件と異なる仕様をテストによって固定していない。
